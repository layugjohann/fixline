# Review routing is decided by fixed rules, not by the model's confidence score

Whether a Proposal is applied automatically or sent to the Review Queue is decided by deterministic rules in code. The rules read the agent's categorical labels (Urgency, match type, an explicit "uncertain" flag), not a numeric confidence the model reports about itself, because LLM self-reported confidence is poorly calibrated. The current rules:
- Auto-apply clear new routine/urgent Work Orders, and obvious matches to an existing Work Order from the same Tenant.
- Send to review: anything flagged uncertain, any match to a Work Order raised by a different Tenant, any Message from a sender not in the Property Roster, every Draft Reply, and any possible duplicate (`possible-duplicate`): a create with the same Location (the same Unit, or the same Common Area) and the same Trade as an open Work Order on the Board, or as another create in the same Proposal.
- Emergencies are applied immediately and also flagged for a human.

The possible-duplicate rule backstops missed matches. When the agent misses that a Message is about an open Work Order, it proposes a create, so no match is proposed and the match rules can't fire. Without this rule the duplicate would be auto-applied, whatever the model's quality: even a model that rarely misses a match gets its misses through. The rule accepts false positives, such as a real second plumbing problem in a Unit that already has an open plumbing Work Order, because one Coordinator click to approve it is cheaper than dispatching the same fix twice. Who raised the open Work Order and its Urgency don't matter, and closed Work Orders never match. Intake reads the Board's open Work Orders and passes them to the rules, so the rules themselves stay pure. Approving from the Review Queue doesn't re-run the rule, because the check against the current Board at approval covers anything that changed meanwhile.

When one Proposal triggers both the emergency rule and a review rule, the Proposal is split. Only the operations that create emergency Work Orders are applied immediately and flagged. Every other operation in the Proposal goes to the Review Queue under the rules that sent it there. So an emergency doesn't wait for review, and it doesn't carry a cross-Tenant match or an unknown Sender's other changes onto the Board unchecked. The split applies to every review rule:
- **Unknown Sender:** an emergency from a Sender not in the Property Roster is still created, because a gas leak reported by a visitor must reach the Board. The Sender's other operations wait for review.
- **Uncertain:** if the agent flags a Proposal as uncertain and it contains an emergency, the emergency is still created and flagged. The Coordinator handles any doubt about it after the fact.
- **Draft Replies:** these always go to review, including Draft Replies that accompany an emergency.
- **Possible duplicate:** an emergency create that is itself a possible duplicate is still created, and its flag shows `possible-duplicate`, so the Coordinator can merge it after the fact. A non-emergency possible duplicate alongside an emergency waits in the Review Queue. Each part carries the rule when one of its own creates is a possible duplicate, including of a create the split put in the other part, so a match within the Proposal isn't lost.

So a single Proposal can end up partly applied: the emergency operations are on the Board while the rest are pending in the Review Queue.
